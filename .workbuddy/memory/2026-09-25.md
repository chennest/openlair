## 日历徽标视觉返工：先对齐方向（方案 A）

### 起因
超哥看截图后觉得"不太好看"，让我放大核对。放大确认了 5 个问题（按严重度）：

1. **配色语义撞车（最严重）**：节日 `#c93400`（红橙）与补班 `--heat #ff6b00`（橙）
   **几乎同色但语义相反**（节日=休，补班=上班）；且红橙读起来像报错而非放假。
   中国日历惯例是「休=红、班=灰/蓝」，我此前做成了三色混战。
2. **字号太小**：桌面 `0.6rem`≈9.6px、移动端 `0.5rem`=8px —— 8px 中文字形已崩，
   这就是截图上「中秋」看着像「中秒」的真因（不是 media query 失效）。
3. **信息密度失衡**：9 月 8~9 个周末格全标「休」，真信号只有 9/20 一颗「班」，被噪音淹没。
4. **位置不符合肌肉记忆**：节日名应在数字**下方**（手机自带日历/企微都如此），我放在了右边。
5. **顶栏与日历两套视觉**：顶栏「上班」蓝底 vs 日历「班」橙底，同一概念两个样子。

另发现既有问题：格子 104px 高但内容只占顶部 30px，上重下空，选中态大蓝框把它放大。

## 认知纠偏：丑的不是徽标，是格子本身

超哥看了 gpt-image 出的两张图后仍觉得"有点丑"。复盘发现问题定位一直错了 ——
我连续几轮都在打磨一个 10px 的徽标，但**真正的视觉问题是格子信息架构**：

1. **格子 104px 高，内容只占顶部 30px** → 每格大片留白，整张日历像"骨架"
2. **日期数字缩在左上角** → 不成列不成行，看着散
3. **完全没有网格线** → 数字像漂浮在空白里，不像日历
4. **选中态是一整格大蓝框** → 把"空"放大到极致，最扎眼（截图里 24 号那格）

→ **结论：光调徽标配色救不回来，必须动格子本身。**
重构稿 `.design/calendar-redesign.png`（PIL 精确渲染，脚本 `make-redesign.py`），要点：
- 数字**水平居中**，节日名/班**居中在数字下方**（此前是贴数字右侧）
- 加**淡网格线**（#f2f2f4）给日历骨架
- 格子高度 104px → 84px
- 选中态**只留数字上的蓝圆点**，去掉整格大蓝框

方法论教训：**定位视觉问题时先看信息架构（留白/对齐/结构），再看装饰细节（颜色/字号）。**
在错误的层级上迭代，越调越精致但仍然丑。

### 🐛 顺带修掉一个既有 bug：移动端网格溢出、末两列被切
**症状**：390px 视口下 grid 385px > 容器 362px，周六/周日两列被卡片裁掉。
**根因（排查了 6 轮）**：`.ev-title` 用 `white-space: nowrap`，其**固有最小宽度**把格子撑到 55px
（7×55=385）。`min-width: 0` 不解决——因为表格的固有 min-content 计算不看 flex 的自动最小尺寸。
**修法**：`.ev-title { width: 0; flex: 1 1 0; min-width: 0; overflow: hidden; text-overflow: ellipsis }`
→ grid 385 → 336，正好放下。
**排查手法（值得复用）**：用 playwright 注入 `<style>` 逐个子元素 `display:none!important`，
每次读 `getBoundingClientRect().width`，二分定位到具体元素。比读 CSS 猜快得多。
> 该 bug 是**既有问题**（事件条撑宽），只因之前的真实数据当月没有日程所以没暴露。
