## 修 bug：词书卡片模式按钮撑破卡片（16:40，超哥截图反馈）

**现象**：卡片里「跟打/听写/自测/默写」4 个按钮整体右溢出，最后一个按钮跑到卡片白色背景外面。

**原因**：`.mode-row { grid-template-columns: repeat(4, 1fr) }` —— `1fr` 等价 `minmax(auto, 1fr)`，那个 `auto` 最小尺寸 = 条目的 min-content。条目是 `Button size="sm"`（`px-2.5` 10px×2 + `gap-1` 4px + `BookOpen` 图标 14px + 文字 2 个 CJK 字 28px + border 2px ≈ 68px），4×68 + 3×8 gap = 296px > 卡片内宽 210px（`card-wall` 最小 250px − padding 40px），轨道被 min-content 顶开 → 溢出 86px，和截图吻合。

**修法（BookCard.vue）**
1. 轨道 `repeat(4, minmax(0, 1fr))` —— 允许收缩到 0
2. 按钮加 `min-w-0`（覆盖 grid item 自动最小尺寸）+ 内边距 `px-2.5` → `px-1`
3. 删掉 `BookOpen` 图标（4 个按钮都挂同一个图标 = 纯装饰，违反「先留白与层级，再考虑图标」；顺手也省 18px）
4. `.book-card` 加 `min-width: 0` 兜底，防其他内容把卡片顶宽

修后单格 = (250−40−24)/4 = 46.5px，按钮 min-content ≈ 38px（28 文字 + 8 内边距 + 2 边框）→ 余量 8.5px。

**同类隐患扫过**：模块内共 3 处 `grid-template-columns`（BookCard、index.vue 的 `auto-fill minmax(250px,1fr)`、QuestionCard 的 `repeat(2, minmax(0,1fr))`），只有 BookCard 这一处有问题，其余已经是 `minmax(0,…)` / 有 min 兜底。

**教训（值得记住）**：**grid 里塞按钮这类「有 min-content 下限」的条目，`repeat(N, 1fr)` 会按 min-content 撑开轨道并溢出容器；要么写 `minmax(0, 1fr)` + 条目 `min-w-0`，要么把条目的图标/内边距压到能塞进最窄轨道。** `pnpm run build` 通过（勾掉未用的 BookOpen import）。

### 调研结论（别人家的瀑布流）
| 实现 | 代价 | 适合 |
|---|---|---|
| CSS `columns` | **列优先填充，打乱键盘 Tab 顺序** | 纯图片画廊 |

## 修 bug：顶部统计条数字叠字（17:10，超哥截图反馈）

**现象**：`词汇练习` 页顶部统计条里「今日练词」和「今日正确率」两格数字叠在一起，截图里显示成 `1090%`；箭头指着那个位置。超哥原话「我要是复习了 1000 个呢？我要是变成 100% 了，你是不是又叠起来了？」——**结论：会，位数一多必然叠。**

**根因（StatStrip.vue）**：
```css
.stat { flex: 1; min-width: 0; }   /* ← min-width: 0 是元凶 */
```
`.stat` 是 `.stat-strip` 的 flex 项，写 `min-width: 0` 等于**允许它被压缩到内容宽度以下**；而里面的 `.big-num` 是 `2.1rem/700` 大字号、`overflow` 默认 `visible` → 一旦数字变长（4 位数、`100%`），文字直接**溢出到相邻格上**，两列叠字。另外 `.stat-strip` 没设 `flex: none`，会被父级 `.page-head` 再压一道。

**修法（StatStrip.vue）**：
1. `.stat` 删掉 `min-width: 0` → 回到默认 `min-width: auto`（= min-content），数字再长只会把列**撑宽**，永不叠
2. `.stat-strip` 加 `flex: none` —— 不被 `.page-head` 压缩，宁可换行也不重叠
3. 间距从 `gap: 8px` 改为 `.stat { padding: 0 14px }` + 条 `padding: 14px 8px`，分隔线两侧有呼吸空间（首尾视觉内边距仍约 22px ≈ 原 20px）
4. `.stat-strip.bare .stat { padding: 0 }` —— bare 变体无分隔线，不需要额外间距

**代价（记下来别再纠结）**：列宽由内容决定，**不再严格等宽**。要等宽又能容纳 4 位数，只能把整条撑到 `N × 最宽列`，纯 CSS 表达不了。不等宽是避免重叠的必要代价，统计条本来也不要求等宽栅格。

**通用教训**：**flex 项上写 `min-width: 0`（或 `overflow: hidden` 的搭档写法）是"允许内容溢出并压到邻居身上"的开关。当子内容是「不可断行 + 大字号」的文本（数字、百分比、金额）时，`min-width: 0` 会让它溢出叠字；这种场景要留默认的 `min-width: auto`。**`min-width: 0` 只在"内容是长英文单词/长 URL，需要省略号截断"时才该用。

| openlair 现状 `learning_steps=()` | **直接 Review，2 天** | **Review，1 天**（没重学！） | 2→11→45→158→492 天 |
| TypeWords `['1m','10m']` | Learning step=1，**10 分钟** | Learning step=0，**1 分钟** | 10min→2d→11d→41d→146d |

⇒ **openlair「答对一次就掌握」的根因 = `learning_steps=()` 把巩固步全省了**：一次 Good 就是 `state=Review` + 2 天，之后按 stability 指数拉开（第 3 次就 45 天）。另外**后端确实没有任何自动写 `status` 的代码**（`submit_answer` 全程不碰 status，`services/vocab.py:278-293`）—— mastered 只能由 `update_progress` 手动标记产生，与上一轮查生产库的结论一致。

**给超哥的改造提案（等他确认后才动代码）**
- 把"是否掌握"从 FSRS stability 手里拿回来，改用**显式连续答对次数**：新表字段 `correct_streak`（答对 +1 / 答错归零）、`required_streak`（识词选对=3、选错/不认识=5）、`identify_result`；`streak >= required` → 自动 `status='mastered'`。
- 未掌握期间 **due 封顶到次日**，否则 FSRS 的 2→11→45 天曲线会让"再复习两遍"变成两个月。
- 首次识别步骤复用现有 `self_test` 交互（已满足"只给单词不显释义"），加一个「不认识」按钮。
- 待他拍板：① 两遍/四五次是**跨会话**（推荐，按天排课架构）还是**同一会话内分钟级复刻 TypeWords**；② 是否允许自动置 mastered；③ 阈值 3 / 5 是否合适。
