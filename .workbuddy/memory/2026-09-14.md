**验证**：`pnpm run build` 通过；并 grep 构建产 CSS 确认 `status.ts` 里的色调 utility 都被 Tailwind 生成（从 .ts 里取类名可行，Tailwind v4 自动扫描）

**两条重要结论（写进后续规范）**
- **shadcn 组件根是 reka `Primitive`，父组件 scoped 类打不进去**（`overview/index.vue` 里有原始注释）；给 `Button/Badge/Progress` 加样式优先走 Tailwind utility。已因此把 `days` 那种 `.new-btn { box-shadow }` 写法在本模块改成 `shadow-[var(--sh-cta)]`
- **不要用「构建产 CSS 的字节顺序」推断 Tailwind 类冲突**（我踩了这个坑）：`cn()` = `clsx + twMerge`，冲突在**合并期**就按「后者胜」消解掉了，根本不会同时落到 DOM 上。实测 `twMerge('bg-secondary text-secondary-foreground','bg-[var(--heat-bg)] text-[var(--heat)]')` → 只留后者；`rounded-md` + `rounded-full` → 只留 `rounded-full`。所以全仓 `<Button class="rounded-full">` 的胶囊是**真的生效**，不是假象。要判断哪个类生效，直接跑 tailwind-merge 验证，别查 CSS 偏移
- 差异未被误判：`rgba(255,59,48,0.0x)` 是本仓既有惯例（calendar/ledger 都在用），**不算**硬编码违规；`days` 的 `.chip`、`notes` 的 `.tag` 说明模块内自带小 chip 也是允许的

**没做/待办**：本环境无本地 playwright 且 5199 端口 curl 不通（sandbox 网络），**没能出截图**，需超哥自己 `VITE_USE_MOCK=true pnpm run dev` 或连 8001 后端肉眼过一遍；后台 `VITE_USE_MOCK=true pnpm run dev` 用 `&` 起会被随命令结束回收，别指望后台常驻。改完**未提交未推送**。
